|TensorData| B[InferenceEngine]

subgraph Frontend
    A1[Input Source] --> A2[Decoder]
    A2 --> A3[Color Convert]

subgraph InferenceEngine
    B1[Inject States] --> B2[Quantize]
    B2 --> B3[NPU Execute]
    B3 --> B4[Dequantize]

subgraph Backend
    C1[Postprocess] --> C2[Composite]

设计原则：
- Preprocessor 只负责空间变换（resize, letterbox）
- Engine 负责精度变换（normalize, quantize, dequantize）
- Backend 负责数据提取 + 合成输出
- 三者正交，互不依赖

### **4. InferenceEngine: NVI + Factory Pattern**

<!-- 填入：
- NVI（Non-Virtual Interface）模式：Infer() 公开入口 → 注入状态 → DoInfer() 纯虚钩子 → 捕获状态
- 工厂模式：make_engine() 根据 INFERENCE_BACKEND 配置创建不同引擎
- 三路引擎：onnx | rknn-zerocopy | rknn-non-zerocopy

关键设计决策：为什么 Normalize + Quantize 放在 Engine 里？

| 引擎 | 输入量化方式 | 输出反量化方式 |
|------|------------|--------------|
| RKNN Zero-Copy | 手动：(pixel-127.5)/127.5/scale+zp 写入 DMA | 手动：(val-zp)*scale 从 DMA 读出 |
| RKNN Non-Zero-Copy | rknn_inputs_set(pass_through=0) | rknn_outputs_get(want_float=1) |
| ONNX Runtime | 模型内嵌 QDQ 节点 | 模型内嵌 QDQ 节点 |

如果把 normalize 放到 Preprocessor 里，换引擎就要改 Preprocessor → 违反"换引擎只需重新编译"的设计目标。
-->
