Sherpa ASR在三款Rockchip SoC上的实现

  • 作者: Potter White
  • 日期: 2025年7月~8月

项目概述

这是一份详尽的技术报告，记录了将 Sherpa ASR 语音识别框架（涵盖 sherpa-onnx 与 sherpa-ncnn 两种后端）部署到三款不同硬件架构与市场定位的嵌入式AI平台上的全链路工程实践。

项目由我独立负责，完整覆盖了从 V1.0 的上层应用架构设计，到 V2.0 的底层平台移植与编译问题排查，再到 V3.0 核心的AI模型自主转换与图优化 的三个主要阶段。项目旨在为公司核心产品赋能AI能力，通过严谨的技术预研、系统实现与深度优化，最终交付了高性能、高稳定性的服务模块，并沉淀了一整套可复用的工程方法论与核心代码库。

核心技术成果

  • 系统级构建与产品化： 独立设计并实现了一套包含并发处理、IPC通信的C/S架构，将一个基础的AI推理SDK（sherpa-onnx）成功集成为一个稳定、可独立部署的服务。

  • 底层并发问题的分析与解决： 利用 Valgrind/helgrind 等动态分析工具，系统性地定位并修复了多个在并发场景下由阻塞式I/O和资源竞争引发的死锁与数据竞争问题，确保了服务的生产级稳定性。

  • 复杂的跨平台交叉编译与适配： 面对不同目标平台（ARMv8/ARMv7）的老旧工具链（GCC 8.3）、不兼容的GLIBC版本以及存在源码缺陷的依赖库（onnxruntime），通过修改构建脚本、手动移植代码补丁等手段，成功完成了复杂的交叉编译工作。

  • AI模型转换与图优化： 实现了从动态输入ONNX模型到静态RKNN模型的自主转换。通过深入分析decoder模型的动态控制流（If算子）与RKNN优化器（fold_constant）的冲突机制，引入onnx-simplifier专业工具，解决了因模型结构复杂导致的转换失败问题。

  • 跨平台性能验证与决策： 在 RK3588s 平台上，通过NPU加速 sherpa-onnx 实现了 RTF 0.2 的高性能。在 RV1126 平台上，通过对 sherpa-ncnn 纯CPU方案的性能测试，明确了其在多任务并行场景下的性能瓶颈。基于此结论，针对 RV1126bp 平台，项目直接跳过了CPU方案验证，将技术重心放在了NPU方案的实现上。

项目三阶段技术纪实

本作品集由三个逻辑递进的章节组成，完整呈现了我在不同平台上面对的核心挑战与解决方案。

  1. 第一章：系统架构与集成 — 在RK3588s上构建高性能 sherpa-onnx 服务

    • 核心问题： “如何从一个SDK，构建一个完整的生产级系统？”
    • 内容简介： 本章聚焦于项目的V1.0阶段，以RK3588s平台为目标，详细阐述了如何围绕一个核心AI SDK，从零开始设计客户端/服务器架构、将核心功能模块化封装为可复用库，并解决了高并发服务中的线程安全、资源管理和优雅停机等关键工程问题。

  2. 第二章：平台移植与问题排查 — 向RV1126平台的适配与 sherpa-ncnn 方案实现

    • 核心问题： “当首选技术路径因平台差异不可行时，如何进行系统性地问题分析并实现备选方案？”
    • 内容简介： 本章记录了项目V2.0阶段的完整调试过程。在将系统移植到RV1126平台时，原定的NPU方案（sherpa-onnx）因SDK版本不兼容而中止。报告详细复盘了转向纯CPU方案（sherpa-ncnn）后，如何解决一系列交叉编译难题，并最终定位和解决了因Debug模式导致的严重性能问题的全过程。

  3. 第三章：自主模型转换 — 为RV1126bp实现NPU加速

    • 核心问题： “如何通过模型层面的分析与优化，解决特定硬件平台的适配障碍？”
    • 内容简介： 鉴于V2.0在RV1126上已确认CPU性能不足，项目V3.0针对具备新一代NPU的RV1126bp平台，直接挑战NPU方案。本章深度剖析了decoder模型因包含动态控制流算子而导致RKNN转换失败的根本原因，并展示了如何通过系统性的技术探索，最终确定并实施了“固定尺寸 -> onnx-simplifier专业简化 -> RKNN转换”的有效流程，成功为该平台实现了模型转换。

核心技术栈

  • 语言与系统工程: C++17, Linux, POSISockets, 多线程并发编程, CMake, GTest, Valgrind, Helgrind

  • AI框架与工具链: Sherpa-ONNX, Sherpa-NCNN, ONNX, RKNN Toolkit 2, onnx-simplifier, Python

  • 硬件平台: 项目涉及三款具有显著架构差异的Rockchip SoC平台，具体规格如下：

    平台型号CPU 架构关键特性NPU 工具链
    RK3588sARMv8-A (64-bit)高性能八核 (4xA76 + 4xA55)rknn-toolkit2
    RV1126ARMv7-A (32-bit)高性价比四核 (4xA7)rknn-toolkit
    RV1126bpARMv8-A (64-bit)衍生型号，四核 (4xA53)rknn-toolkit2

  • 架构与方法论: 客户端/服务器架构, 模块化库设计, 系统整合, 根本原因分析 (RCA)
