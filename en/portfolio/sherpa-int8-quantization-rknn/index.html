End-to-End INT8 Quantization and Deployment of a Streaming ASR Model (Sherpa-ONNX Zipformer) on an Embedded Platform (RV1126B)

This project delivered the end-to-end INT8 quantization and deployment of the Sherpa-Zipformer streaming ASR model. By modifying the C++ inference backend and designing a ‘Simulated Streaming Method’ for calibration, this work resolved critical failures caused by a lack of state continuity. The final deliverable is a high-performance INT8 RKNN model for the RV1126B platform, achieving an RTF of 0.29.

Project Name: End-to-End INT8 Quantization and Deployment of a Streaming ASR Model (Sherpa-Zipformer) on an Embedded Platform (RV1126B)

  • Author: PotterWhite
  • Date: Aug-Sep 2025
  • Tech Stack: RKNN-Toolkit2, ONNX, C++, Python, librosa, sherpa-onnx, LibriSpeech, AiShell
  • Project Type: Model Deployment, INT8 Quantization, Embedded AI, Inference Engine Integration

1. Project Objective

To convert a FP32 precision streaming Zipformer ASR (Automatic Speech Recognition) ONNX model to an INT8 precision RKNN model for an embedded device based on the Rockchip RV1126B SoC. The goal was to complete the deployment and validation within the sherpa-onnx C++ inference framework to meet low-latency and low-power operational requirements.

2. Methodology & Workflow

This project adopted a systematic approach, covering the entire process from model analysis, runtime environment adaptation, and calibration data generation to final model validation.

3. Implementation & Key Findings

3.1 Initial Model Conversion

  • Action Taken: Attempted to directly convert the officially released int8.onnx model using rknn-toolkit2.
  • Observation: The conversion failed. The toolchain reported an error, indicating the model contained a DynamicQuantizeLinear operator, which is incompatible with the static graph computation model of the RKNN NPU.
  • Resolution: Determined that the FP32 ONNX model must be used as the input source, leveraging the native static quantization capabilities of rknn-toolkit2.

3.2 C++ Inference Framework (sherpa-onnx) Adaptation

  • Action Taken: After successfully converting the FP32 model to an INT8 RKNN model, inference was performed in sherpa-onnx.
  • Observation: A runtime error occurred with the message Unsupported tensor type: 2, INT8.
  • Resolution:
    1. Modified the sherpa-onnx RKNN backend C++ source code, adding logic to handle the RKNN_TENSOR_INT8 data type in the processing of model inputs, outputs, and states.
    2. Implemented a manual dequantization step after retrieving model outputs. This step used the scale and zp (zero_point) parameters from rknn_tensor_attr to convert INT8 outputs back to the FP32 data required by subsequent decoding logic.

3.3 Iteration and Optimization of the Quantization Calibration Dataset

This was the core phase of the project, where an effective calibration data generation scheme was identified through multiple iterations.

  • Iteration 1: Snapshot Dataset

    • Method: Extracted multiple feature frames (x) from audio as calibration samples. All state inputs (cached_* tensors) were populated with zero tensors.
    • Result: The resulting INT8 model produced garbled or silent output during inference.

  • Iteration 2: Precise Feature Extraction + Snapshot Dataset

    • Method: Performed an in-depth analysis of the sherpa-onnx C++ source code (features.h). The audio preprocessing pipeline, including Remove DC Offset and Pre-emphasis, was precisely replicated in the Python data generation script. State inputs were still zero-padded.
    • Result: Inference results did not improve, proving that the authenticity of the state tensors was a more critical factor.

  • Iteration 3: Simulated Streaming Dataset

    • Method: Developed a Python script to fully simulate the streaming inference process of sherpa-onnx using onnxruntime. At each time step, the authentic feature frame (x) and the authentic non-zero states (cached_*) computed by onnxruntime from the previous step were saved as a complete set of calibration samples.
    • Result:
      • After quantizing with the full dataset generated by this method (sampling_interval=1), the model successfully produced complete and intelligible recognition results for the first time, with a Real-Time Factor (RTF) of approximately 0.29.
      • The dataset size was extremely large (>100GB), leading to conversion times of several hours.

3.4 Further Exploration of Quantization Strategies

Based on the successful interval=1 dataset from section 3.3, the following strategy tuning was performed:

  • Quantization Algorithm:

    • normal (default): Successfully generated the model, with results as described in 3.3.
    • kl_divergence: Failed during the conversion process due to an Out of Memory (OOM) error. Analysis indicated that this algorithm requires loading a large number of samples into memory for statistical calculation, making it incompatible with the large-scale dataset.

  • Data Sampling Methods:

    • Systematic (sampling_interval > 1) / Random Sampling: Attempted to reduce the dataset size through sampling to accommodate the kl_divergence algorithm.
    • Result: Although the conversion succeeded, the resulting model’s inference output reverted to garbled text. This indicated that the Zipformer model is highly sensitive to the Temporal Continuity of states in the calibration data.

  • Mixed-Precision Quantization:

    • Method: Attempted to use the manual and automatic mixed-precision features of rknn-toolkit2 to keep sensitive operators like Softmax in FP16.
    • Result: Manual mixing did not significantly improve accuracy and introduced new recognition errors. The model generated by automatic mixing produced runtime errors or garbled output.

4. Project Outcome & Conclusion

  • Final Deliverables:

    1. A stable INT8 RKNN ASR model capable of running on the RV1126B platform with an RTF of 0.29, successfully achieving the deployment from FP32 to INT8.
    2. A validated Python script (09_generate_calibration_dataset.py) for generating calibration datasets for streaming stateful models, which ensures the authenticity and continuity of state tensors by simulating streaming inference.

  • Engineering Conclusions:

    1. For this Zipformer model, the authenticity of states and temporal continuity of the calibration data are the decisive factors for successful quantization, holding greater importance than minor variations in feature extraction.
    2. Statistical quantization algorithms in rknn-toolkit2, such as kl_divergence, have memory limitations when processing large-scale, high-dimensional, continuous datasets.
    3. Given the current toolchain and model architecture, using a complete simulated streaming dataset in conjunction with the normal quantization algorithm represents the optimal engineering solution, achieving the best balance between conflicting constraints (accuracy, performance, and conversion feasibility).
