Implementation of Sherpa ASR on Three Rockchip SoCs

  • Author: Potter White
  • Date: July-August 2025

Project Overview

This is a detailed technical report documenting the end-to-end engineering practice of deploying the Sherpa ASR speech recognition framework (covering both sherpa-onnx and sherpa-ncnn backends) onto three embedded AI platforms with distinct hardware architectures and market positioning.

I was solely responsible for this project, which fully encompassed three main phases: from V1.0’s high-level application architecture design, through V2.0’s low-level platform porting and compilation troubleshooting, to V3.0’s core AI model conversion and graph optimization. The project was aimed at empowering the company’s core products with AI capabilities. Through rigorous technical research, system implementation, and in-depth optimization, I ultimately delivered a high-performance, highly stable service module and established a reusable set of engineering methodologies and a core codebase.

Core Technical Achievements

  • System-Level Build and Productization:
    Independently designed and implemented a C/S architecture featuring concurrent processing and IPC communication, successfully integrating a basic AI inference SDK (sherpa-onnx) into a stable, independently deployable service.

  • Analysis and Resolution of Low-Level Concurrency Issues:
    Systematically identified and fixed multiple deadlocks and data races caused by blocking I/O and resource contention in concurrent scenarios using dynamic analysis tools like Valgrind/helgrind, ensuring production-grade service stability.

  • Complex Cross-Platform Cross-Compilation and Adaptation:
    Successfully completed complex cross-compilation by modifying build scripts and manually porting code patches to overcome challenges on different target platforms (ARMv8/ARMv7), including outdated toolchains (GCC 8.3), incompatible GLIBC versions, and dependency libraries with source code defects (onnxruntime).

  • AI Model Conversion and Graph Optimization:
    Achieved the independent conversion of dynamic-input ONNX models to static RKNN models. By deeply analyzing the conflict mechanism between the decoder model’s dynamic control flow (If operator) and the RKNN optimizer (fold_constant), and by introducing the professional onnx-simplifier tool, I resolved conversion failures caused by the model’s complex structure.

  • Cross-Platform Performance Validation and Decision-Making:
    On the RK3588s platform, achieved a high performance of RTF 0.2 with NPU-accelerated sherpa-onnx. On the RV1126 platform, performance testing of the pure CPU solution (sherpa-ncnn) identified its performance bottlenecks in multi-task parallel scenarios. Based on this finding, the project directly skipped the CPU solution for the RV1126bp platform, focusing technical efforts on implementing the NPU solution.

Project Three-Phase Technical Chronicle

This portfolio piece is composed of three logically progressive chapters, presenting the core challenges I faced and the solutions I implemented on each platform.

  1. Chapter 1: System Architecture and Integration — Building a High-Performance sherpa-onnx Service on RK3588s
  • Core Problem: “How to build a complete, production-grade system from a single SDK?”
  • Content Summary: This chapter focuses on the V1.0 phase of the project, targeting the RK3588s platform. It details how I designed a client/server architecture from scratch around a core AI SDK, encapsulated core functionalities into a reusable library, and solved key engineering challenges in high-concurrency services, such as thread safety, resource management, and graceful shutdown.
  1. Chapter 2: Platform Porting and Troubleshooting — Adapting to RV1126 and Implementing the sherpa-ncnn Solution
  • Core Problem: “When the primary technical path is unfeasible due to platform differences, how do you systematically analyze the problem and implement an alternative solution?”
  • Content Summary: This chapter documents the complete debugging process of the project’s V2.0 phase. When porting the system to the RV1126 platform, the original NPU plan (sherpa-onnx) was abandoned due to SDK version incompatibility. The report provides a detailed retrospective on how I overcame a series of cross-compilation challenges after switching to a pure CPU solution (sherpa-ncnn) and ultimately identified and resolved a severe performance issue caused by a Debug mode build.
  1. Chapter 3: Independent Model Conversion — Achieving NPU Acceleration for RV1126bp
  • Core Problem:
    “How to overcome hardware-specific adaptation barriers through model-level analysis and optimization?”
  • Content Summary:
    Given that V2.0 had already confirmed the CPU performance was insufficient on the RV1126, the V3.0 phase for the RV1126bp (which features a new-generation NPU) directly tackled the NPU solution. This chapter provides an in-depth analysis of the root cause of the RKNN conversion failure—the decoder model’s dynamic control flow operators. It showcases how, through systematic technical exploration, I ultimately identified and implemented an effective workflow: “Fixed-size input -> onnx-simplifier professional simplification -> RKNN conversion,” successfully enabling model conversion for this platform.
